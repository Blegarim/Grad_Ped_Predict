## How to read this

Each **model** gets one block: a run register (which run dirs fill which cells), the **2×2 cross-protocol
matrix** (train × test over {anchored, streaming}), and the **G-decomposition** of the anchored→streaming
crossing-detection gap.

- **Cells report crosses-only** (the thesis task). Format per cell: `AUC · raw-F1 → tuned-F1`.
  - **AUC** = threshold-free ranking ability (the *diagnostic*).
  - **raw-F1** = F1 at the default 0.5 threshold (the "before recalibration" operating point).
  - **tuned-F1** = F1 at the val-tuned F1-optimal threshold (the "after recalibration" point — the **only
    reportable** threshold-tuned number, per the M2 val-never-test rule). `oracle_*` same-split sweeps are
    excluded on purpose.
- **G-figures** are measured in **tuned-F1 on the test=streaming column** (F1 is the currency recalibration
  acts on; AUC is the explanation, never quoted *as* a G). All three are deltas of the two anchored→streaming
  numbers plus the streaming-trained number:
  - `G_total   = (streaming-trained, streaming-test, tuned-F1)  −  (anchored-trained, streaming-test, RAW-F1)`
  - `G_prior   = (anchored-trained, streaming-test, tuned-F1)   −  (anchored-trained, streaming-test, RAW-F1)`  ← recalibration-fixable part
  - `G_hardneg = (streaming-trained, streaming-test, tuned-F1)  −  (anchored-trained, streaming-test, tuned-F1)`  ← residual hard-negative skill gap
  - By construction `G_total = G_prior + G_hardneg`.

**What all four runs share** (verified in the four `resolved_config.yaml` snapshots): `pose_full` with the

**Where they differ — the two mismatches, both inside Model B:**

\* **Selection metric.** `20260721` records `selection_metric=macro_f1` while `active_tasks=[crosses]`.
Because macro-F1 averages only the active tasks, it collapses to crosses-F1 — so the *effect* is the same
as its partner's `crosses_f1`. This mismatch is cosmetic.

† **Weighted sampler (the one that matters).** `20260721` (anchored) trained with
`use_weighted_sampler=false`; `20260714_134253` (streaming) trained with `use_weighted_sampler=true`. The
sampler oversamples the rare crossing windows, so Model B's two halves did **not** see comparably balanced
training streams. Model A's halves both have it off, so Model A is unaffected. See the caveat list for what
this does and does not invalidate.

## Model A — pose_full, 3-head (macro_f1 selection)

|---|---|---|

| G | arithmetic | value |
|---|---|---|

ranking collapse on streaming negatives. Explains why G_prior ≈ 0: recalibration can't rescue a model that
can no longer rank.

## Model B — pose_full, crosses-only

**Cells: `AUC · raw-F1 → tuned-F1`** (crosses, test split)

| | test = anchored | test = streaming |
|---|---|---|
| **train = anchored** (`20260721_123011`) | 0.880 · 0.716 → 0.721 | **0.529 · 0.064 → 0.062** |
| **train = streaming** (`20260714_134253`) | 0.679 · 0.258 → 0.428 | **0.784 · 0.249 → 0.225** |

**G-decomposition** (tuned-F1, test=streaming):

| G | arithmetic | value |
|---|---|---|
| **G_total** | 0.225 − 0.064 (raw) | **+0.161** |
| **G_prior** | 0.062 − 0.064 (raw) | **−0.001 (≈0)** |
| **G_hardneg** | 0.225 − 0.062 | **+0.162** |

**AUC diagnostic (anchored-trained):** 0.880 (test-anchored) → **0.529** (test-streaming) — same near-chance
collapse as Model A.

**Read this matrix with care (corrected 2026-08-18).** It removes one confound and adds another:

- *Removed:* no multi-task interference — only the crossing head is trained, so nothing about these numbers
  can be blamed on the walking/looking heads.
- *Added:* the two halves used **different sampler settings** (see the register). The streaming half trained
  with the oversampler; the anchored half did not.

Which way that pushes the numbers is not obvious, and this is worth stating honestly rather than assuming:
oversampling the rare crossing windows usually *helps* rare-class F1, which would inflate `G_hardneg`
(0.162 vs Model A's 0.126, consistent with that direction). But oversampling positives is also a plausible
contributor to the all-positive collapses visible in that run's `train_log.csv` (val_loss spiking to 4–8 on
epochs 1, 2, 4, 13, 17 with recall snapping to 1.0), which would *hurt* it. Both effects may be present.

**Practical consequence:** treat Model A as the headline matrix and Model B as a supporting observation that
the multi-task heads are not what produces the gap. Do not describe Model B as the cleaner or
confound-free measurement. A sampler-matched re-run of the anchored half would settle it.

## Reading of the two models together

Both models agree on the headline: **G_prior ≈ 0, G_hardneg ≈ G_total**, and in both, a model trained on the
anchored benchmark drops to near-chance ranking (AUC ~0.53) when tested on the streaming stream. **Of the
anchored→streaming deployment gap, ~0% is recalibration-fixable and ~100% is a genuine hard-negative skill
gap** the anchored benchmark never trains.

What Model B adds, stated precisely: it shows the gap is **not an artifact of the multi-task heads** — with
only the crossing head trained, the same collapse appears. It is *not* an independent confirmation of the
magnitude, because of the sampler mismatch above. Quote Model A's numbers; cite Model B for the
no-multi-task-interference point.

**Caveats that must ship with these numbers (do not bury):**
1. **Data-volume confound.** The anchored training set is ≈4.9k windows; the streaming one is ≈88k, about
   18× larger. So `G_hardneg` currently mixes together *what protocol the model trained on* and *how much
   data it trained on*. Phrase findings as "consistent with a hard-negative gap," not "proven." The clean
   test is a streaming run subsampled to ≈4.9k windows — matched size, same protocol.
2. **F1 is unstable at a 1-in-37 base rate.** A handful of samples moving across the threshold swings it.
   The AUC reading (0.88 → 0.53, both models) is the more trustworthy number today; average-precision and
   precision-at-fixed-recall are the sharper replacements (Stage 6).
3. **Model B's sampler mismatch** (register footnote †) — the anchored half trained without the oversampler,
   the streaming half with it. Settle it with a sampler-matched re-run of the anchored half before Model B's
   magnitude is quoted anywhere.
4. **Single seed.** Every cell here is `seed=42`, one run. The multi-seed protocol (screen with one, confirm
   with three, report mean±spread) has not been applied to any of these numbers.

**How these numbers are used now (August 2026 reframe).** The decomposition has moved from *the thesis
result* to *the thesis motivation* — it establishes that the problem is real and that recalibration cannot
solve it, which is what justifies building a method. See
[docs/METHODOLOGY.md](../../docs/METHODOLOGY.md). Practically this **lowers** the bar on caveat 1 (a
motivating measurement can carry an acknowledged confound) and **raises** it on caveats 3 and 4, because any
new method will be compared against these runs as baselines — and a baseline with an accidental
configuration difference invalidates the comparison, not just the caveat.

## Adding a new run (do this every eval pass)

1. Run `evaluate.py --split val` then `--split test` on **both** protocols so all four cells exist.
2. Pull `crosses_auc`, `crosses_f1` (raw), `tuned_crosses_f1` from `eval_log.csv` (test rows only).
3. **Diff the config against its partner leg before filling any cell.** A 2×2 is only a comparison if the
   two training runs differ in the training protocol and nothing else. Compare the two
   `resolved_config.yaml` files and record any difference in the register — this is exactly the check that
   would have caught the Model B sampler mismatch in July instead of a month later:
   ```
   diff outputs/runs/<anchored_run>/resolved_config.yaml outputs/runs/<streaming_run>/resolved_config.yaml
   ```
   Expect exactly one difference (`data.protocol`). Anything else is either a bug to fix or a caveat to
   write down, and it must be resolved *before* the G-figures are computed.
4. Add the run to the register; if it completes/extends a model's 2×2, fill the matrix + recompute the
   three G-figures with the arithmetic shown above.
5. Regenerate the machine table: `python -c "from pedpredict.utils.logging import rebuild_index; rebuild_index('outputs/runs')"`.
6. Bump **Last updated**.
